## 題目

**主推**
> 幾何感測器的語意盲區:視覺語言模型於自走車開放詞彙障礙判讀與處置決策之應用

**備選(較短)**
> 視覺語言模型於自走車開放詞彙障礙處置之應用與實測

5G 專網卸載**已完全移除**(2026-07-30):不進標題、不進架構、不進實驗,最多在未來工作提一句。

## 核心主張

> 幾何感測器(深度、光達、封閉集分割)遇到沒見過的東西會「**無聲失效**」;
> 而看得見未見物體的方法(開放詞彙偵測器)仍**無法回答該怎麼處置**。
> VLM 是唯一不需預先列舉,就能直接輸出「處置等級 + 可稽核理由」的一層。

**主張定位在決策層,不在偵測層。**(2026-07-30 修正)

「只有 VLM 看得到未見物體」這句話**擋不住** YOLO-World / Grounding DINO 等開放詞彙偵測器,
不可使用。可防守的版本是逐層剝奪:

| 方法 | 為什麼不夠 |
|---|---|
| 幾何(深度/分割) | 不知道那是什麼 → 無聲失效 |
| 封閉集偵測器(COCO)+ 類別→等級查表 | **查表本身就是封閉集**,只是把「預先列舉」從模型搬到規則;且**類別標籤不帶狀態** |
| 開放詞彙偵測器 | **要你先給詞彙表**,同一個問題換件衣服;輸出仍是類別,不是處置 |
| **VLM** | 不需列舉,直接輸出 L0/L1/L2 + 文字理由 |

VLM 的價值**不在**偵測「哪裡有東西」(那是深度相機的工作),而在回答:

1. 那是**什麼**
2. **能不能過**
3. **要不要通報**

其中第 2、3 點取決於**狀態**而非類別 —— 水泥乾的還是未凝固、積水淺的還是深的、
袋子空的還是裝滿的。任何以「類別」為輸出的方法在定義上都拿不到狀態。

## 三個貢獻

1. **任務定式化** — 把「幾何感測器的語意盲區」定義成可量測的三級處置任務,綁定車輛實際行為而非抽象判斷。
2. **系統架構** — 事件觸發的感知堆疊:常駐廉價訊號(深度幾何 + 外觀異常)只負責**觸發**,
   VLM 卸載到 **Gemini API** 推論。並將系統可行性拆成**三個可量測的成立條件** ——
   **觸發涵蓋**(逐物件觸發召回率、誤觸發率)、**延遲**(端到端實測 + 換算成車輛前進距離)、
   **成本**(每次呼叫)—— 逐一驗證,而非僅作架構描述。
   ~~5G 專網三層卸載~~ 已於 2026-07-30 完全移除(見 E3′)。
3. **可解釋輸出與實證評估** — VLM 產生人類可讀的處置理由(命中主題 1 的可解釋 AI 子領域),
   並在真實校園自走車平台上量化相對封閉集 baseline 的增益與成本。

## 三級處置定義(核心設計)

| 等級 | 判定 | 車輛動作 | 範例 |
|---|---|---|---|
| **L0** | 可直接通行 | 不減速 | 落葉、淺水痕、路面標線、影子、人孔蓋 |
| **L1** | 可自行繞行 | 觸發繞障(`ros_test_bypass.py`) | 紙箱、三角錐、垃圾桶、停放腳踏車、塑膠袋 |
| **L2** | 需停車並通報 | 停車 + 送出文字描述 | 人、動物、施工圍籬、施工濕水泥、玻璃碎片、橫向繩索 |

**為什麼用三級而不是「要不要通報」**:抽象的「是否需通報」ground truth 太主觀,審稿人必打標籤效度。
綁定車輛行為後,標註規則可操作化(物體高度、能否壓過、是否為人、是否為施工),且直接對應既有繞障邏輯。

## 系統架構

```
RealSense D435i(深度 + 彩色)
        │
        ▼
車上 Jetson Orin Nano:深度幾何 + 外觀異常 常駐(觸發層)
        │  兩訊號任一異常且通過去彈跳/走廊/冷卻條件 → 觸發事件
        │  車輛同時減速
        ▼
    網路卸載
        │
        ▼
Gemini VLM API ──→ 三級處置 L0/L1/L2 + 文字理由 ──→ 回饋車上 ──→ 執行
```

> **實作範圍(2026-07-30 定案)**:VLM 推論**只用 Gemini API 一條路徑**。
> 車上本地 VLM 與 5G 專網中繼伺服器**已全部移除**,不在架構圖、不在實驗、不在貢獻。
> 若在論文提及 5G,只能寫在未來工作,且不得暗示已實作。

**事件觸發的必要性 = 成本,不是準確度。** VLM 一次推論數百毫秒到數秒,加上網路來回;相機是 30 fps。
常駐跑 VLM 在物理上不成立。此論證不需要 VLM 比 baseline 準,只需要 VLM 比 baseline 貴。

### 為什麼用雲端 API 而不是車上 GPU(2026-07-30 定案論證)

**這條論證必須是正面的設計推導,不能寫成「因為跑不動所以只好用 API」** —— 後者讀起來是限制,前者是設計。

**論證鏈(四步,環環相扣):**

1. **任務需要的是強模型,不是任何 VLM**。本文的關鍵案例是**狀態判讀** ——
   水泥乾/未凝固、積水淺/深、袋子空/裝滿。這些是細粒度語意,
   **2B 級的車載小模型極可能答不出來**,而那正是本文貢獻所在的案例。
2. **強模型放不進 Jetson Orin Nano** —— 8 GB 記憶體由 CPU/GPU 共用,
   只裝得下量化後的 2B 級模型。
3. **因此語意層必須離車** → 產生延遲與金錢成本。
4. **因此必須事件觸發,不能常駐** → 回到觸發層設計。

**API 是第 3 步的結論,不是妥協。** 而且注意:**用 API 反而讓成本論證更強** ——
車上 GPU 持續低頻推論在買下硬體後近乎免費,雲端 API 是**每次呼叫都計費**,
「不能常駐」在**經濟上**而不只在算力上成立。

**其他可寫的正面理由**
- **可重現性**:指名版本的 API 模型,他人可重現;手工量化的本地 build 難以重現
- **可升級**:語意層更新不需動車輛
- **車隊經濟**:一個強模型服務 N 台車,勝過 N 顆 GPU

**必須誠實載明的代價(不寫會被問)**
- **網路相依**:斷線即無語意層。**緩解 = 退回 B1 的幾何行為**(即本車現行邏輯),
  屬 fail-safe 降級,不是失效。這句話要寫,它同時證明 B1 baseline 的存在有系統上的必要性。
- **延遲變異**:E3′ 除中位數外**必須報 p95 與逾時/失敗率**,否則審稿人會問校園網路的穩定性。

**若時間有餘(選配,砍序最前)**:在 Orin Nano 上跑一個 2B 級量化 VLM,
作為 4.3 的**額外對照點**,展示「小模型延遲低但狀態判讀失敗」的取捨。
**不得列為必要工作** —— 它需要數天的環境建置且可能失敗,7/30 已確認不納入主線。

### 觸發層設計(2026-07-30 新增 — 回應「誤觸發」問題)

**問題**:分割模型訓練不足會在真實路面上產生破洞,導致明明是路卻觸發 VLM。**這一定會發生。**

**為什麼不致命**:觸發層是**高召回、低精確**的過濾器,兩種錯誤的代價不對稱 ——

| 錯誤 | 後果 | 代價 |
|---|---|---|
| **誤觸發**(是路卻觸發) | VLM 回 L0,車繼續走 | 一次 API 呼叫 + 短暫減速 → **成本問題** |
| **漏觸發**(有障礙卻沒觸發) | 系統根本沒問 VLM,障礙被忽略 | **安全問題** |

所以觸發層刻意偏向寧可多觸發。**論文要明講這個不對稱,它就是觸發層設計的正當性來源。**

**壓低誤觸發的四個條件**(★ = 本文有量測;其餘為設計說明,論文須明寫未量測)

1. ★ **行駛走廊** — 異常需落在車前方預定行駛走廊內,且面積大於門檻(濾掉路邊破洞)
2. ★ **雙訊號** — 深度幾何異常**或**外觀異常;兩者皆可單獨觸發(理由見下)
3. **去彈跳** — 異常需**連續 N 幀**成立才觸發(濾掉單幀分割抖動)
4. **冷卻** — 觸發後 T 秒內不對同一區域重複觸發

> 3、4 是**時間條件**,單幀靜態資料集量測不到。論文只描述設計,
> 並明寫「其效果未於本文量測」。**不可暗示已驗證。**

**為什麼觸發層不能只用深度(關鍵,原架構的隱藏漏洞)**

P02(壓扁的紙箱)、P03(空塑膠袋)、P06(地面標線與橫過路面的延長線)**在幾何上幾乎是平的**,深度**看不到或極微弱**。
若觸發層只靠深度,這三對根本不會觸發 → VLM 連被問的機會都沒有 → 整條管線在最能展現
VLM 價值的案例上直接失效。**因此外觀訊號(分割覆蓋率/異常)必須留在觸發層。**

> 注意這與「把 `best.pt` 從 baseline 移除」不衝突:分割在本文有**兩個不同角色** ——
> 作為**觸發訊號**保留(系統的一部分),作為**處置決策 baseline**移除(它本來就不是幹這個的)。

**外觀訊號的經驗依據 —— 2026-07-29 初步實測(僅 4 張,非統計結論)**

拿實拍影像跑 `best.pt`:

| 畫面 | sidewalk 覆蓋率 | grass 覆蓋率 |
|---|---|---|
| 空景 | **55.0%**(conf 0.76) | 26.9% |
| 加入站立的人(2 m) | **0%** | 23.0% |
| 加入蹲著的人(2 m) | **0%** | 24.2% |

**失效方式與原先預測不同**:不是「把人標成 `road`」的局部誤判,而是**整片地面分割崩潰**(55% → 0%)。

這筆數據在本文有兩個用途:

1. **證明覆蓋率是可用的觸發訊號** —— 55% → 0% 是極大的訊號變化,`MIN_ROAD_COVER` 這類門檻抓得到。
   這是「分割覆蓋率異常」能當外觀訊號的**唯一經驗依據**,E4-1 的門檻掃描要從這裡起步。
2. **證明幾何/封閉集的無聲失效**(前言動機、圖 2) —— 下游只看到「road coverage 崩掉」,
   而這個訊號**無法區分**:路被擋住/路面結束/相機故障/進入未訓練場景。
   封閉集模型無法表達「這裡有東西但我不認識」,只能讓整個場景信心崩潰。

> **限制**:僅 4 張,且未檢查是否為信心閾值造成。**不可當作結果寫進論文**,
> 需以 E1 完整資料集重測後才能引用數字。空景 sidewalk 55% 亦順帶確認**拍攝地點是 in-distribution**的。

### 文獻與業界先例(2026-07-30 查證 — 觸發不是本文發明,要引用)

**先分清兩種模式,本文屬 B,不可混寫:**

| 模式 | 做法 | 代表 |
|---|---|---|
| **A. 非同步低頻** | VLM **持續**跑,但頻率低於控制迴路,用非同步融合吸收延遲 | Figure Helix(System 2 VLM **7–9 Hz** / System 1 **200 Hz**)、NVIDIA GR00T N1(VLM **10 Hz** on L40 / DiT **120 Hz**)、DriveVLM-Dual |
| **B. 事件觸發**(**本文**) | 廉價監測器常駐,**只有事件成立才呼叫** VLM | Sinha et al. RSS 2024、Think When It Matters(2026) |

**最關鍵的一篇 —— 與本文架構幾乎相同,必引:**

> Sinha, Elhafsi, Agia, Foutter, Schmerling, Pavone,
> *Real-Time Anomaly Detection and Reactive Planning with Large Language Models*, **RSS 2024**(arXiv:2407.08735)

兩階段:**快速二元異常分類器常駐** → **觸發**慢速生成式 LLM 做 fallback 選擇。
論文明講兩個動機與本文完全一致:(i) 降低基礎模型線上運行的計算成本、(ii) 把它的判斷納入安全控制框架。
它用 **MPC 維持多條 fallback 計畫的可行性**來吸收慢推論的延遲 ——
**本文的對應做法是「觸發後先減速再等判斷」,是低速平台上的簡化版,要在 4.3 明講此對應關係。**

**其他可引的實測數字**

- **DriveVLM-Dual**(Tsinghua MARS Lab,arXiv:2402.12289):實車部署於**雙 OrinX**,
  高頻端到端在 OrinX-1、VLM 在 OrinX-2,兩者**非同步協作**,VLM 平均推論 **410 ms**
- **Think When It Matters**(Ahmadi et al., Sorbonne, 2026-07, arXiv:2607.10991):
  **鄰近距離觸發**(PSC 門檻),實機 Mirokaï + ROS2。VLM 單次 **2,425 ms**(彩色深度輸入)/
  **4,580 ms**(RGB)。門檻 0.80 m → 約 **1,090 次**呼叫;放寬到 0.90 m → **3,250 次**
- **Slow Brain, Fast Planner**(arXiv:2606.20458):明講「**VLM 每次查詢 1–3 秒,無法直接驅動
  5–20 Hz 控制迴路**」;**校園人行道**移動機器人實測,延遲 5 s 內成功率仍 >80%

**這對本文的三個影響**

1. **觸發機制不是本文的新穎點,不可宣稱為貢獻** —— 它是既有做法。引用後**反而可以寫短**:
   「本文採用文獻中已確立的事件觸發架構 [X][Y]」一句帶過,省下的版面給表 3。
2. **本文的成本論證比多數文獻更強**:模式 A 那些系統把 VLM 跑在**車上 GPU**,持續低頻近乎免費;
   本文卸載到**計費的雲端 API**,常駐在**經濟上**也不可行。這是本文情境的真實差異,值得寫一句。
3. **「觸發門檻掃描」有現成先例**(Think When It Matters 的 0.80 vs 0.90 m 消融)—— 見 E4-1。

### 哪些可以引用、哪些必須自己量(2026-07-30 — 回答「觸發條件與成效可否引用」)

**分界線:設計與理據可以引用,成效必須自證。**
成效是**你這套訊號、你這個門檻、你這批物件**的性質,不是架構的性質。

| 項目 | 可引用? | 說明 |
|---|---|---|
| 兩階段架構(廉價監測器 → 觸發昂貴模型) | **✅ 引 Sinha RSS 2024** | 不必重新論證此架構合理 |
| 「觸發層應高召回、低精確」的設計原則 | **✅ 引** | 誤觸發是成本、漏觸發是安全,此不對稱是通則 |
| VLM 延遲量級(1–3 s、410 ms) | **✅ 引** | 用來說明為何不能常駐 |
| 門檻掃描消融**這種做法** | **✅ 引** Think When It Matters | 方法論先例 |
| **你的觸發召回率 / 誤觸發率** | **❌ 必須自己量** | 取決於 `best.pt` 在你的路面、D435i 在你的光線 |
| **你的門檻數值** | **❌ 必須自己掃** | 對方的 0.80 m 是社交導航的人身距離,與覆蓋率異常門檻無關 |
| **積水/壓扁紙箱這類平面物體會不會觸發** | **❌ 必須自己量** | 沒有任何論文能替你證明這件事 |

**為什麼不能借對方的成效數字**:Sinha 的快速分類器跑在 **LLM embedding 空間**、
資料是四旋翼與自駕車;你的訊號是**分割覆蓋率 + 深度幾何**、資料是校園磚道。
訊號不同、領域不同、門檻不同 —— 引用其數字當作自己系統可行的證據是**無效推論**,審稿人會當場抓到。

**判準(可推廣到論文其他地方)**

1. 由**定義或建構**即成立 → 不需驗證(例:幾何感測器輸出不含語意)
2. 文獻在**相同設定**下已建立 → 可引用(例:兩階段架構的合理性)
3. 取決於**你的資料、硬體、參數** → **必須量測**(例:觸發召回率)

觸發成效毫無疑問屬第 3 類。**好消息是它很便宜** —— EMPTY 空景 6 張 + 沿路負樣本 34 張 + 配對組影像,約 2 小時腳本(見 E4-1)。

**引用 Sinha 反而降低風險**:明講「觸發架構為採用而非本文發明」,
就不會被讀成與 [9] 競爭;本文的貢獻在**三級處置任務**與**已見/未見消融**,不在觸發機制。

**必須誠實量測並載明的限制**:壓扁紙箱、空塑膠袋、地面標線、橫過路面的延長線這類**平貼地面、外觀變化弱**的目標,可能兩個訊號都觸發不了。
因此 E4 要報**逐物件的觸發召回率** —— 若某物件根本觸發不了,後段 VLM 再準也沒用。這是本系統
的真實邊界,主動報比被審稿人問出來好。

### E2 能力對照(主結果)

**設計修正(2026-07-29)**:原本把 `best.pt` 當「對手」是**稻草人** — 它是路面分割模型,
本來就不是拿來避障的,審稿人會直接以此否定。改為**消融實驗**架構。

**主張不是「VLM 比較準」,而是「幾何在原理上無法區分」。**

**設計再修正(2026-07-30 第二次)**:原 C1–C5 五階梯縮為 **B1–B3 三階梯**。
兩個理由:(1) 本文主題是**障礙處置**,不是路面分割 —— 把「分割單獨」列為配置等於在比一個
沒人拿來做這件事的東西;(2) 「深度單獨」不構成一個能輸出處置等級的系統,它是 B1 的零件不是配置。
**6 頁上限也不允許五列的主表。**

**三個配置嚴格巢狀(B1 ⊂ B2、B1 ⊂ B3),每階只多加一個語意層:**

| 配置 | 內容 | 能回答 | 不能回答 |
|---|---|---|---|
| **B1** | **深度 + 幾何規則**(地面上方高度門檻) | 前方有沒有東西、多高、要不要繞 | 那是什麼 → **紙箱 vs 蹲著的人 完全無法區分** |
| **B2** | B1 + **COCO 偵測器 + 人工「類別→等級」查表** | COCO 80 類涵蓋的物體(人、狗、腳踏車…) | 未列舉的類別、以及物體的**狀態** |
| **B3** | B1 + **VLM(Gemini API)** | 完整三級處置 + 文字理由 | — |

**B1 不是為了論文捏造的稻草人,是本車現行的避障邏輯** —— `ros_test_bypass.py` 就是深度 ROI
高度判斷 + `/scan` 光達後方淨空確認。論文要明講這點:baseline 是**已部署的系統**,不是假想敵。

**B2 為什麼必須加上深度,不能只有 COCO**(回應「可以只用 COCO 嗎」)

COCO 偵測器輸出的是 **2D 邊界框 + 類別**,不含距離。只有它的話:

- 不知道那個人在 **1 m 還是 20 m** 外 → 無法決定要不要停
- 不知道物體是否在**行駛走廊內** → 路邊的人會被當成擋路
- **COCO 認不得的東西完全不輸出** → 紙箱、三角錐、水泥直接消失,系統以為前方淨空

所以真實系統一定是**融合**:深度負責「有東西、在哪、多高」,偵測器負責「那是什麼」,
認不得時**退回 B1 的高度規則**當通用障礙處理。這樣 B2 才是真正的強 baseline,
而且與 B1 巢狀 —— B2 的失敗只可能來自語意層,不會來自「它連東西都沒看到」。

**B2 是防守關鍵,不加會被一擊斃命。** 審稿人第一句必然是「P01/P05 的難點是人,
隨便一個 COCO 預訓練 YOLO 就有 `person`,為什麼需要 VLM?」——**這句話是對的**。

**B1 與 B2 都必須給予最有利設定,並在論文寫明**:B1 的高度門檻在本資料集上掃描取最佳值,
B2 的類別→等級查表由人工精心撰寫。這樣它們的失敗才是**原理性的**,堵死「你 baseline 沒調好」。

**`best.pt` 分割的去處**:移出 baseline 階梯,改放在
(1) **前言的動機示例** — 紙箱被自信地標成 `road`,即圖 2 左半,以及
(2) **觸發層的外觀訊號**(見「觸發層設計」)。
它在本文是**問題的證據與系統的零件**,不是對手。

### 為什麼不用光達?(回應「要不要證明」)

**不需要實驗證明,而且不該試圖證明。** 用實驗說「光達比較差」會立刻被問「你用哪顆、裝多高、
掃描線幾線」,反而製造破口。正確做法是**從輸出空間論證**,一段話寫在 B1 的說明裡:

> 光達與深度相機同屬幾何感測器,輸出為**佔據與距離**,不含語意。本文對 B1 的論證
> ——「幾何量測無法區分處置等級相反但幾何相近的物體」——**對光達同樣成立**,
> 因為限制來自輸出空間而非量測精度。二者差異在感測範圍、精度與對材質的敏感度,
> 不在能否回答「那是什麼」。本車的避障實作(`ros_test_bypass.py`)實際即同時使用
> 深度與 2D 光達,B1 代表的正是這一類方法。

**這是定義性論述,審稿人接受度高;宣稱「光達偵測不到」才需要實驗,而我們不做那個宣稱。**

### 單一地點拍攝(2026-07-30 定案 — 修正前一版的說法)

**前一版寫「三個地點要看起來不一樣」是把問題講反了。** 正確的理解:

怕的是**混淆變數** —— 把已見物件拍在 A 地、未見物件拍在 B 地,
則 B2 在未見組表現差時,分不出是「COCO 不認得」還是「B 地較難」。
**解法是「每個物件都在同一個地方拍」,所以單一地點反而完全消除這個混淆。**
單一地點的代價只是**泛化性**,那是限制一節的一句話,不是方法瑕疵。

**負樣本的「多樣性不是張數」則仍成立,但同樣不需要換地點**:
誤觸發率的分母若都是同機位同角度,統計上等於 1 張。
解法是**沿同一段路移動、每 ~3 m 停一次換朝向拍**。

**定案:單一地點,124 張,約 1 小時 30 分。** 完整排程見 `paper/拍攝作業手冊.md` §1.6。

| 項目 | 數量 |
|---|---|
| **14** 個障礙物件 × **3 距離(1/2/3 m)× 2 橫向** | 84 |
| EMPTY 空景(同機位 2 朝向 × 3) | 6 |
| 負樣本(沿路每 3 m 停一次,含草地/人行道) | ~34 |
| **合計** | **124** |

**已見 5 物件(30 張)vs 未見 9 物件(54 張)**。

- **已見組涵蓋 L1(腳踏車/背包/雨傘)與 L2(蹲著的人/站立的人),沒有 L0** ——
  已見組的 L0 由**無障礙負樣本**(空路面)承擔,論文要這樣寫。
  (先前版本寫「兩組皆有 L0/L1/L2 涵蓋」是**錯的**,已見組從來就沒有 L0 物件。)
- **未見組涵蓋 L0/L1/L2,但 L2 只有「延長線」一項** —— 見下方風險。

**距離由 4 檔砍為 3 檔(去掉 5 m)** —— 戶外強光下 D435i 在 5 m 的深度品質不可靠,
拍了也進不了 B1/B2。這不是為了省時間,是那批資料本來就用不上。

**限制一節要寫**:資料採自單一校園單一地點,泛化能力未驗證;樣本量小,不宣稱過度。

**若現場改為兩個地點(2026-07-31 補充規則)**

- **程式面**:`--location` 是啟動參數,跑起來之後不能改。必須**離開程式重跑**並輸入新的地點代號,
  否則第二個地點的資料會全部被標成 `location=A`。每個地點**都要先拍 6 張 EMPTY**
  (`last_empty_ref` 每次執行都從空字串開始)。
- **論證面**:**物件組不可以跨地點拆開**。把已見物件拍在 A、未見物件拍在 B,
  會讓「B2 在未見組差」分不出是 COCO 認不得還是 B 地較難 —— 這正是單一地點原本要消除的混淆。
  合法用法只有兩種:(a) **B 地只拍空景與負樣本**(推薦,誤觸發率分母的多樣性變好,零混淆風險);
  (b) **14 個物件在每個地點各拍一次**(完整重複,+84 張,只有要主張跨場景泛化才需要,6 頁放不下)。

**架構檢查(2026-07-31 依刪 P07 後重算)**

B2 預測會**贏 2 對**(P01/P05,都是有人的那兩對)、**輸 3 對**(P02/P03/P06)。
其中 **P02 與 P03 是「狀態配對」** —— 差異不在物體是什麼,而在它的狀態(完整/壓扁、空/滿)。
任何以類別為輸出的方法(**包含開放詞彙偵測器**)在定義上都拿不到狀態。

→ **P02/P03 是唯一能擋住「用 YOLO-World 就好了」這個攻擊的證據,優先序與 P01 同級,絕不能砍。**

### ⚠️ 未見組的 L2 只有 2 個 —— 主表對比仍偏薄(2026-07-31 二次)

深積水與警戒帶皆無法取得。目前未見組的 L2 是 **P06 的延長線**與 **X-L2 的破碎的碗**兩項。

樣本量小,不宜過度推論。

### ⚠ 「已見/未見」的定義必須改(2026-07-30 稽核發現)

**問題**:這個軸原本是相對 **`best.pt` 的訓練類別**(grass/road/sidewalk)定義的。
但 `best.pt` 已移出 baseline 階梯 —— **這個軸現在懸空了**,B1 是純幾何、根本沒有類別概念。

**修正:改為相對 B2 的 COCO 80 類定義。** 這樣才與階梯一致,而且意義更好:

| 組 | 定義 | 本文物件 |
|---|---|---|
| **已見(COCO 涵蓋)** | 在 COCO 80 類中 | 蹲著的人、站立的人、**腳踏車、背包、雨傘**(**共 5 項**) |
| **未見(COCO 未涵蓋)** | 不在 COCO 中 | 紙箱、完整紙箱、壓扁紙箱、空塑膠袋、裝滿的塑膠袋、垃圾桶、地面標線/影子、**橫過路面的延長線**、**破碎的碗/碎陶片**(**共 9 項**,後兩項是未見組僅有的 L2) |

**為什麼這樣才對**:表 2 要說的故事是「**B2 在已見組表現好,在未見組崩掉;B3 兩組都平**」。
只有把軸定義在 B2 的類別集合上,這個故事才成立。原定義下 B1/B3 對該軸完全無感,表 2 會沒有意義。

**連帶問題:已見組樣本太少。** 原本只有人×2 = 2 個物件(12 張),未見組 8 個物件(48 張),
嚴重不平衡 → **加拍 3 個 COCO 涵蓋的物體:腳踏車、背包、雨傘**(各 6 張,共 +18 張),
已見組補到 5 個物件 30 張。三樣校園裡都好取得,`bicycle`/`backpack`/`umbrella` 都在 COCO 內。
腳踏車本來就寫在三級處置定義的 L1 範例裡,補拍它同時填了那個空。

> **第三項 COCO 物體改過兩次**:`chair`(椅子)→ `potted plant`(盆栽)→ **`umbrella`(雨傘)**,
> 都是因為現場取得不到。挑選條件有兩個:**(a) 在 COCO 80 類內、(b) 搬得動**
> (所有障礙物件都要擺到車前 1/2/3 m,固定式的長椅 `bench` 雖然在 COCO 內卻搬不動,
> 會破壞「同一地點同一機位」的控制)。
> 其他可替換的選項:`suitcase`(行李箱)、`sports ball`(球)、`handbag`(手提包)。
> **不建議 `bottle`(水瓶)** —— 3 m 處太小,偵測失敗會變成尺寸問題而非語意問題,論證會被模糊掉。

**「已見類別對照(純路面/草地/人行道)」的角色也要改**:
它原本是給 `best.pt` 的對照,現在改為 **無障礙負樣本**,兩個用途 ——
(1) **E4-1 誤觸發率的分母** —— 與 EMPTY 空景合併,共 **6 + 34 = 40 張**無障礙影像(依 `拍攝作業手冊.md` §1.6 定案);
(2) B1/B2/B3 在無障礙時**不該誤報**的正確率。**繼續拍,但論文裡的說法要改。**

**指標**
- 三級處置正確率(分已見/未見兩組,**依上表的 COCO 定義**)
- **無聲失效率** — 錯得很有信心的比例
- **配對區分率** — 同一對內兩者是否被給不同等級
- **主表:B1→B2→B3 在已見/未見兩組上的表現差異**
- **逐對表:B2 vs B3 在 5 對(P01/P02/P03/P05/P06)各自的區分結果** — 這張才是擋開放詞彙攻擊的關鍵
- **觸發層獨立指標**:逐物件觸發召回率、誤觸發率(見「觸發層設計」與 E4)

**為什麼這樣改就打不倒**:B1 是本車實際部署的幾何避障方案、B2 是實務上會採用的偵測器融合方案,
兩者都不是稻草人;而配對設計讓它們的失敗變成**原理上必然**,不是調參數能解決的。
審稿人無法說「你 baseline 沒調好」,也無法說「你在比一個沒人這樣用的東西」。

### E3′ 卸載延遲與行為可行性(2026-07-30 大幅縮減)

~~原設計:三層卸載(Jetson 本地 GGUF / 5G 中繼 / 公有雲)全測,含抖動、可用性、功耗。~~

**砍掉的理由是成本嚴重不對稱,不是這些數據沒價值**:
公有雲 API 延遲半天可測(在家就能做);5G 中繼那層必須在場域,且「中繼機能否同時連專網與外網」
**至今未驗證**,是未知數;Jetson 本地那層要在 Orin Nano 上把量化 VLM 跑起來,可能吃掉兩三天**而且會失敗**。
5G 不進標題、不是主軸(見「投稿標的」),不值得吃掉初稿時間。

**改測三件事:**

1. **公有雲 VLM API 端到端延遲**(觸發 → 回傳處置),n≈50,報中位數與 p95
2. **換算成車輛行為** — `LANE_SPEED_V = 0.15 m/s` × 延遲 = 等待期間前進距離
   (延遲 2 s → 0.3 m),配合「觸發後先減速再等判斷」的設計論證可行性
3. **一次閉迴路實車示範** — 觸發 → VLM 回 L1 → `ros_test_bypass.py` 實際繞行,錄影

**用最慢的那層(雲端)來論證「不能常駐」反而更強。** 第 3 點是防止整篇被讀成「一篇 API 評測」的關鍵:
它證明三級處置真的綁定車輛行為,而不只是紙上分類。素材與推甄作品集共用。

### E4 系統成立條件:觸發、延遲、成本(2026-07-30 三次改版 — 升格)

**定位修正**:E4 原本被當成「附加的成本統計」,一度還被我判為可砍。**這是錯的判斷。**
E2 證明的是「**問到 VLM 時**它答得比較好」;但實車上 VLM 會不會**被問到**,由觸發層決定。
兩者之間有一道縫,審稿人只要問一句就會裂開:

> 「表 3 說 B3 在 P02(壓扁的紙箱)贏,但你的觸發層看得見一張攤平的紙板嗎?看不見的話,
> 實車上 VLM 根本不會被呼叫,你的增益在部署時等於零。」

**所以三個前提是主張的必要條件,不是配菜**:觸發是否涵蓋、延遲是否可接受、成本是否可負擔。
任何一項不成立,E2 的結論就只在離線資料集上成立,無法外推到系統。

**用詞警告**:**不可宣稱觸發「完整」**。完整性無法證明,只能報涵蓋率。
可寫的是「本文 14 個障礙物件中觸發召回 X/14,未觸發者為 Y、Z,列為系統邊界」(配對組 10 + X-L2 1 + COCO 組 3)。

#### E4-1 觸發涵蓋(必要條件,權重最高)

| 指標 | 資料來源 | 現場成本 |
|---|---|---|
| **逐物件觸發召回率** — 14 個物件各自能否觸發 | 配對組 10 + X-L2 1 + COCO 組 3 的影像(已在拍) | **0** |
| **誤觸發率** — 真實路面被誤判為異常的比例 | **EMPTY 空景 6 張 + 沿路負樣本 34 張 = 40 張**(已在拍) | **0** |

**加碼(幾乎免費,且有文獻先例)**:把觸發門檻**掃過一遍**,畫出
「觸發召回率 vs 誤觸發率」的取捨曲線 —— 資料同上,只是換參數重跑。
先例是 Think When It Matters 的門檻消融(0.80 m → 1,090 次呼叫;0.90 m → 3,250 次)。
有了這條曲線,E4-1 就從「兩個數字」變成一個**可辯護的設計取捨**,而且直接回應
「你門檻是不是調過頭」這種質疑。若版面不夠,曲線可只用文字報三個代表點。

**兩個數字都能從靜態資料集算出來,不需要行駛 rosbag。** 單幀評估不涉及時間條件,
所以去彈跳與冷卻**不在此量測範圍**,論文要明寫「實車部署另加時間條件,本文未量測其效果」。
腳本約 2 小時。

**預期會有壞消息**:壓扁紙箱、空塑膠袋、地面標線、橫過路面的延長線這類平貼地面或外觀變化弱的目標可能觸發不了。
**其中延長線與破碎的碗最要緊** —— 它們是未見組僅有的兩個 L2,兩個都觸發不了的話,未見 L2 就完全沒有證據。
**這是要主動報的結果,不是要藏的失敗** —— 它界定了系統的真實邊界,也是本文與純 benchmark 的差別。

#### E4-2 延遲(可行性條件,權重中)

見 E3′。重點是換算成車輛行為:`0.15 m/s × 延遲 = 等待期間前進距離`。
**這個條件很容易滿足** —— 觸發後先減速再等判斷,幾秒的延遲在低速平台上都可接受。
不要把它寫得像個難題,誠實說「在本平台的速度下不構成限制」即可。

#### E4-3 成本(權重最低,但要有數字)

- **每次呼叫成本**:token 數 × 官方定價 → 可直接算,無需額外資料
- **每公里呼叫次數**:**需要一段行駛 rosbag**(現場 10 分鐘)
- 對照:常駐跑 VLM 的理論成本(30 fps × 單價),用來證明不可行

> **需要你現場決定**:若要報「每公里成本」,就得錄那段 10 分鐘的行駛 rosbag
> (color + depth,或至少 `/floor_info` 的 coverage 序列)。
> 不錄的話,成本只能報「每次呼叫」,並在限制寫明未量測實際觸發頻率。
> **我先前建議完全不錄,在「三個前提要完整」的框架下該建議已作廢。**

## 拍攝作業

完整流程、配對清單、張數、現場測試、驗收檢查見 **`paper/拍攝作業手冊.md`**
(2026-07-30 新建,內容已更新;貼進 Notion 子頁「拍攝作業手冊(現場用)」後兩邊一起維護)。摘要:

**四條鐵則**
1. **必須用車上的 RealSense D435i 拍,不可用手機** — `best.pt` 是在這顆相機的視角與高度上訓練的,
   換相機會引入 domain shift,失效原因將無法歸因。
2. **必須同時存彩色 + 對齊的深度** — 深度基線(B1/B2)與觸發機制都要用。
   已由 `segmentation/capture_paper_dataset.py` 實作(彩色 + 對齊深度 + `intrinsics.json`);
   舊的 `collect_floor_dataset.py` 只存 Color,**不可用於本次拍攝**。
3. **相機裝在車上的實際位置與高度**,不可手持。
4. **一律加 `--seg`** —— 圖 2(全篇唯一的定性圖)需要 `seg_vis/` 裡
   「紙箱被自信標成 `road`」那張疊圖。指令:`python3 capture_paper_dataset.py --location A --seg`
   **代價**只是預覽變慢(分割在主迴圈逐幀同步跑,非 worker thread);車靜止拍照無所謂。

## 風險與對策

| 風險 | 對策 |
|---|---|
| **再次換題或擴大範圍** | **目前最大風險**。17 天內不得再改主線;Aurora 可用不代表要把 SLAM 加回主線 |
| **雲端 API 在場域連不上或延遲爆掉** | 退回 B1 的幾何行為(fail-safe 降級,見「為什麼用雲端 API」);延遲以 p95 與逾時/失敗率誠實報告,主結果 E2 為離線評估、不受影響。~~中繼機連不出去~~ 已隨 5G 移出本文範圍 |
| **審稿人說「用現成 COCO 偵測器就好」** | **已納入為 B2 baseline**。不加這個對照組是原架構最大的洞 |
| **B2 表現超出預期** | 若 B2 連 P02/P03/P06 也贏,主結果會被削弱。**先試拍 10 張(5 對各 2 物件)跑 B2 再決定正式拍攝規模** |

| **延長線或破碎的碗觸發不了** | 它們是未見僅有的兩個 L2,兩個都失敗等於未見 L2 零證據。E4-1 要**單獨報這一項的觸發結果**,並在拍攝時多換幾個角度與背景對比 |

| VLM 對 prompt 敏感 | 報告換 prompt 的變異,避免被質疑挑結果 |

## 題目為什麼站得住(緒論素材)

**對手是誰,為什麼會輸**

| 任務 | 有便宜 baseline 嗎 | 該不該用 VLM |
|---|---|---|
| 偵測 SLAM 退化區 | **有** — ORB 門檻、geofence | 否 — 舊主線被放棄的原因 |
| 判斷路面可不可走 | **有** — `best.pt` 分割 | 否 |
| 偵測前方有障礙 | **有** — 深度、光達 | 否 |
| 辨識常見物體(人、狗、腳踏車) | **有** — COCO 預訓練偵測器 | 否 |
| 偵測未列舉的物體 | **有** — 開放詞彙偵測器(YOLO-World / Grounding DINO) | 否 |
| **判斷物體的狀態**(水泥乾/濕、積水淺/深) | **沒有** — 類別式輸出在定義上不帶狀態 | **是** |
| **從未列舉的觀察直接產出處置等級** | **沒有** — 類別→等級查表本身就是封閉集 | **是** |
| **要不要通報** | **沒有** | **是** |
| **可稽核的文字理由** | **沒有** | **是** |

> **不可使用的說法**:「只有 VLM 偵測得到未見物體」——開放詞彙偵測器做得到,這句會被當場推翻。
> 正確說法見「核心主張」:VLM 的不可取代性在**決策層**與**狀態判讀**,不在偵測層。

**為什麼實驗一定測得出差距**:封閉集分割在未見類別上**必然**失敗 — 這是定義問題不是機率問題。
模型輸出空間裡沒有該類別,只能把紙箱歸成 road 或 grass,且信心分數很高。
這種「無聲失效」正是安全上最危險的失敗模式,也是本文要量化的東西。

**已知弱點(論文中主動承認)**
- 新穎性有限:open-vocabulary obstacle understanding 在國際上非新題目;定位於國內研討會 + 真實車輛平台實證。
- 樣本量小、人工標註引入主觀性、VLM 對 prompt 敏感、文字解釋的 faithfulness 未驗證。
